# 課題と結果の対応付け

課題の識別子を `set_id / entry_id`、結果の識別子を `result_id` としています。同じtask_idを再利用した改訂・再実行を、別の課題エントリとして区別します。

## 対応の根拠

| 方法 | 確認内容 |
| --- | --- |
| HASH_MATCH | 実行記録のtask_sha256と元の課題定義のSHA-256が一致 |
| EXPLICIT_ENTRY_KEY | 実行記録に明記された課題キーが一致 |
| ENTRY_DIRECTORY | 同一実験・実行回内の課題ディレクトリにある結果 |
| SET_AND_ENTRY_ID / SET_AND_UNIQUE_TASK_ID | 同一セット内の一意の課題IDによる対応。定義全体のhash一致を意味しない |

個別記録の抽出元ファイルのSHA-256とJSON内の位置を保持しています。元の定義hashが記録されていない場合に、hash照合済みとは表示しません。定義hashが異なる結果は代表結果から除外します。

## 照合の範囲

- 48セット・619課題エントリの全てに、結果への参照または未確認の表示を用意しました。
- 607エントリに、結果または明示的な未実行・停止・対象外の記録が対応します。成功件数ではありません。
- 12エントリは課題別結果未確認です。いずれもメモリ条件比較のrun-001に属し、起動条件確認時の停止記録があります。後続runの結果を割り当てていません。
- 抽出記録1926件の出典690ファイルについて、ファイルhash、JSON内の位置、課題ID・ディレクトリ・実行キーの対応を検査しました。
- 同一課題の複数モデル・工程・保存形式を含むため、1926件は独立した実行回数ではありません。
- レビュー実験のARE-009〜011の対照記録は、収録した8課題の定義と対応しないため、その結果として割り当てていません。

対応が確認された記録の一例として、連続稼働セットでは52課題・Local採用51件、委譲手順v2.2.6のfull-002では13課題・変更なし採用8件が、課題別記録と実験の総括で一致します。これらは個別実験の確認であり、全セットの性能値ではありません。

## 比較時の注意

結果表はLocal実装、コードの検証、レビュー判断、工程全体の品質、実行状態を区別します。LocalのPASSだけで最終採用とは扱いません。テストの設計不備やインフラ障害も別の状態として残します。

代表記録は工程ごとに、課題別の集計、実行履歴、個別結果の順で選び、二次的な記録もJSONに保持します。元の集計が過去の工程を再利用している場合、独立した再実行として合計しないでください。

CSVのreported_credits・input_tokens等は、出典に記録された測定値だけを転記しています。cost_field、usage_field、wall_fieldに元の項目名を示します。レビューだけの費用と工程全体の費用、実測費用と条件付き比較費用を混ぜて合算しないでください。欠測は空欄のままです。

この整備ではモデル評価を再実行していません。[機械的な照合結果](correspondence-audit.json)と[全エントリの収録状況](result-coverage.json)を併記しています。
