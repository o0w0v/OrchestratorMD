# 使い回すタスク分割：6つの型

今回の500件で使った構成を、再利用するための知識として整理する。コードの85/100という結果と、Officeの補助付き・採点不備を含む結果を区別する。以下は自動Routerへの採用決定ではない。

| 型 | Hostが先に用意するもの | Gemmaへ任せる単一の責務 | 必須チェック | 実測からの注意 |
|---|---|---|---|---|
| 小関数 | シグネチャ、型、公開例、境界・異常系テスト | 関数bodyを返す | compile、実行テスト、scope。採用時はfmt/clippyも | 型不一致が残る。COD-025/060は境界・区間集約の誤り |
| 表の1変換 | 入力表、列型、並び順、欠損・重複規則 | filter/sort/groupの1処理 | 行集合、列型、順序、元IDの追跡、合計 | 集約後のID表現まで先に決める。指示と期待表の矛盾をなくす |
| 文章の限定転記 | 出典付き事実、編集欄、残す引用・固有名詞 | 短い説明または差替え文 | 事実欠落、創作、数字、引用保護 | 妥当な別表現を完全一致だけで落とさない |
| レイアウト値 | 図形ID、座標単位、編集可能属性 | 一つの整列・寸法・色の変更 | 範囲内、重なり、native反映、全ページ目視 | JSONが正しくてもHostが無視するとfalse green。変換を先に検証 |
| 数式1列 | 列型、条件の優先順、丸め、参照範囲 | 指定列の式を返す | native再計算、境界値、エラー、循環参照 | 期待結果の計算も独立確認。並び・条件順で失敗例 |
| 複数成果物 | 一つの出典表、共通ID、成果物別schema | 共通データから各欄へ振り分ける | 表と文章とスライドの数値・日付・単位・出典の一致 | WRK-036/045等で説明と表が矛盾。各ファイル単独PASSでは不足 |

共通contractとして、入力hash、許可された編集欄、出力の型と上限、成功条件、触ってはいけない内容を固定する。配列は要素型まで記述する。編集先をモデルに自由選択させない。

複雑な課題は、まず正規化したデータを1回だけ確定し、その同じデータから各成果物へ展開する分割を検討する。整合性チェックはHost側で行う。ただしこの多段構成の経済価値は今回のone-shot結果から証明しておらず、後続の比較対象とする。

知識の登録項目は「適用条件 / 入力型 / 参照 / 編集欄 / 固定検証 / 実測例 / 失敗例 / 準備と検証の費用 / 未検証範囲」とする。成功例だけを登録しない。
